## 1. Обзор

**Жанр:** паркур-раннер с процедурной генерацией и чекпоинтами.
**Платформа:** Яндекс Игры (браузер, десктоп + мобильный веб).
**Целевая сессия:** 3–10 минут.
**Ключевая эмоция:** «ещё один забег», азарт от риска ради очков.

**Elevator pitch:**
Игрок прыгает по процедурно генерируемым чанкам между чекпоинт-платформами. Три единицы здоровья, падение — потеря HP, потеря всех HP — рестарт. Очки за прогресс с множителем от запаса HP. После смерти — рекорд, лидерборд, реклама.

---

## 2. Core loop

```
Старт забега (HP=3, score=0)
        ↓
Прохождение чанка (паркур)
        ↓
Приземление на новую платформу → чекпоинт + score + генерация след. чанка
        ↓
Падение → −1 HP → телепорт на чекпоинт
        ↓
HP=0 → Смерть → экран результата
        ↓
[сохранение рекорда] → [interstitial] → [rewarded-опция] → Новый забег
```

## 3. Механики

### 3.1 Паркур и чекпоинты

- Уровень = последовательность **ключевых платформ** (чекпоинтов), между ними — **чанки** препятствий.
- Приземление на ключевую платформу → `spawnPoint = позиция платформы`, начисление очков, спавн следующего чанка + платформы.
- Падение в килл-зону (ниже уровня чанка) → телепорт на `spawnPoint`, `−1 HP`. Чанк **не** перегенерируется.

### 3.2 Здоровье

- Старт: `HP = 3`, максимум `3`.
- Падение: `HP − 1`. При `HP = 0` — смерть и полный рестарт забега.
- Rewarded-реклама может дать `+1 HP` на экране смерти (опционально).

### 3.3 Очки (score)

- `+100 × hpMultiplier` за каждую пройденную платформу.
- Множитель от текущего HP:

| HP | Множитель |
|----|-----------|
| 3  | ×1.5      |
| 2  | ×1.2      |
| 1  | ×1.0      |

- (Опционально, TBD) бонус за «чистые» прыжки / комбо без падений между платформами.

### 3.4 Рекорд и сохранение

- **Текущий забег**: `score`, `hp`, `spawnPoint` — в памяти, обнуляются при смерти.
- **Рекорд** (`bestScore`): персистентный. Сохраняется **сразу при превышении** (защита от краша) через `player.setData`.
- При смерти, если `score > bestScore` → обновить рекорд + отправить в лидерборд.

## 4. Генерация уровней

**Подход:** пул заготовленных чанков + параметр сложности.

- Чанк = префаб/сцена, состоящая из препятствий (платформы, блоки, уступы).
- Каждый чанк имеет метаданные: `difficulty (1–5)`, `entryPoint`, `exitPoint`, `длина`.
- Сложность следующего чанка выбирается по номеру пройденного чанка (кривая сложности, TBD).
- Генерация «по требованию»: следующий чанк спавнится в момент приземления на текущую платформу, не раньше — экономия памяти.
- Чанк должен быть **гарантированно проходим** (валидация в редакторе / ручная проверка).

**Открытый вопрос:** минимальная длина чанка, чтобы не было «непроходимых» стыков. Решить на этапе прототипа.

## 6. Монетизация (Яндекс Игры)

### 6.1 Реклама

- **Interstitial (`showFullscreenAdv`)** — на экране смерти, **после** показа результата. Частоту контролирует платформа. Не вызывать по таймеру. Не блокировать игру при `onError`.
- **Rewarded (`showRewardedVideo`)** — кнопка «Продолжить с +1 HP» на экране смерти. Награда строго в колбэке `onRewarded`. Частоту вызывать можно свободно.

### 6.2 Правила модерации (обязательно)

- SDK Яндекса подключён; реклама только через SDK.
- Никаких своих кнопок, имитирующих рекламные блоки.
- Награда rewarded — только по `onRewarded`.
- Не показывать рекламу во время активного геймплея.

## 7. Техническая архитектура

### 7.1 Модули

```
GameManager        — состояние забега (HP, score, spawnPoint), переходы экранов
LevelGenerator     — выбор и спавн чанков, кривая сложности
ChunkPool          — пул/кэш чанков, переиспользование
PlayerController   — движение, прыжки, детект приземления и падения
ScoreManager       — начисление, множитель, рекорд, отправка в лидерборд
YandexSDKService   — обёртка над ysdk: init, player, leaderboards, adv
AdManager          — логика interstitial/rewarded, cooldown (если нужен)
SaveService        — облачное сохранение (player.setData) + фолбэк
UIManager          — экраны, HUD
```

### 7.2 Ключевые интерфейсы

```javascript
// YandexSDKService
init(): Promise<void>
getPlayer(): Promise<Player>
saveData(obj): Promise<void>
loadData(): Promise<object>
submitScore(board, score): Promise<void>
showInterstitial(): Promise<{wasShown}>
showRewarded(): Promise<{rewarded}>
```

### 7.3 Структура данных игрока

```json
{
  "bestScore": 0,
  "totalRuns": 0,
  "settings": { "sound": true }
}
```

> `setData` перезаписывает объект целиком — всегда шлём полное состояние.

### 7.4 Требования к производительности

- 60 fps на среднем мобильном вебе.
- Пул чанков: не более N активных одновременно (TBD, ~5).
- Уровень выгружается позади игрока.
